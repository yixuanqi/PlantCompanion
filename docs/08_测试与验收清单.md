# 08｜测试计划、回归用例与验收门禁

## 1. 测试分层

- **Rust 纯逻辑单测**：`LifeEngine` 不读取真实时钟，注入确定事件序列；覆盖所有时间边界、入睡唤醒、死后不可变。
- **集成测试**：睡眠事件适配器、数据库事务、渲染通知、配置迁移与关闭重启。
- **Windows E2E**：透明窗、任务栏、DPI/多屏、锁屏/解锁、休眠/唤醒、系统托盘、开机启动。
- **视觉回归**：小薄荷/小蘑菇在不同分辨率/亮暗背景、每个生命周期阶段和睡眠状态截图对比。
- **性能测试**：5 分钟静置 CPU/内存；10 分钟动画运行；高低帧率对输入流畅度影响。

## 2. 必须自动化的确定性用例

| 编号 | 输入 / 操作 | 期望 |
| --- | --- | --- |
| L-01 | 新植株 `e=0` | HEALTHY；无提醒 |
| L-02 | `e=0.70T-1ms` → `0.70T` | HEALTHY → THIRSTY，一次转场 |
| L-03 | `e=0.90T-1ms` → `0.90T` | THIRSTY → DRY |
| L-04 | `e=T` | 触发一次标准提醒，仍 DRY |
| L-05 | `e=T+10min-1ms` → 边界 | DRY → CRITICAL |
| L-06 | `e=T+20min-1ms` → 边界 | CRITICAL → DEAD；只写一次纪念 |
| L-07 | HEALTHY、THIRSTY、DRY、CRITICAL 各自入睡 12h | 仍为原阶段；`active_elapsed_ms` 不变 |
| L-08 | 从 DRY 进入睡眠再唤醒 | `WAKING` 结束后还是 DRY，剩余时间不跳变 |
| L-09 | 已 DEAD 的实例睡眠/唤醒/喝水 | 返回 REJECT_DEAD，不恢复 |
| L-10 | 锁屏时再手动暂停，随后解锁 | 仍在睡眠，直到手动暂停解除 |
| L-11 | 无输入 10min 且恰好死亡阈值落在窗口内 | 无误死亡；确认空闲后从 last_input_at 冻结 |
| L-12 | 无输入 9min 后恢复操作 | 计入已确认活跃时长，按阶段正常推进 |
| L-13 | 切换系统时钟/夏令时 | 生命周期不突变 |
| L-14 | 崩溃后 8h 再启动 | 未运行时间不计入活动；不触发离线死亡 |
| L-15 | 同一 request_id 连点 10 次 | 最多一笔有效确认和一笔奖励 |
| L-16 | 间隔 <15min 的重复点击 | 无周期重置、无奖励；UI 提示友好 |
| L-17 | 已死 A → 种植同品种 B | A 数据永久 DEAD；B 的 id 全新 |
| L-18 | 写死亡事务中途断电模拟 | 恢复后生命/纪念/账本一致，不会重复处理 |
| L-19 | 暂停时变更提醒间隔 | 新配置按定义生效，不在睡眠期间触发死亡 |
| L-20 | 应用重复重启、窗口隐藏/显示 | 生命状态只以 Rust/数据库为准，无重复通知 |


## 3. Windows 真机操作回归

- [ ] 1920×1080、2560×1440、125%/150% 缩放下不溢出任务栏；支持主显示器与副屏动态插拔。
- [ ] 透明空白区域不会遮挡原桌面交互，盆/叶片可点，拖拽与点击判定无冲突。
- [ ] 锁屏瞬间入睡，解锁正确唤醒；临界状态不趁锁屏死亡。
- [ ] 系统睡眠、休眠、长时间关机后恢复，计时冻结，无大跳变。
- [ ] 自动睡眠阈值跨越时不先判死再撤销，满足 L-11。
- [ ] 手动睡眠与自动睡眠同时存在时不会解锁误解除。
- [ ] 托盘菜单打开设置、切换面板、退出都可靠；退出不会留下幽灵浮窗。
- [ ] 桌面上的全屏应用/游戏时不挡操作；退出全屏后仍能找回植物。
- [ ] 断网状态全功能可用。

## 4. 视觉与动画验收

- [ ] 两个首发植物完全无五官，画风、花盆、边线和配色统一。
- [ ] 各自的 `idle_healthy` 循环无明显跳帧，连续播放 5min 不累积位移。
- [ ] 生命阶段转场不是突兀换图；角色盆底锚点不跳。
- [ ] 睡眠和枯萎图在 96 DIP 也明显不同，睡眠动作不等于下垂失水。
- [ ] 喝水反馈明确但温柔，水滴/叶子/伞帽按角色特征变化。
- [ ] 死亡动画只播放一次，重启和重新打开窗口不重复。
- [ ] 气泡统一奶油手绘风；无默认系统 Toast 风格混用；小字号可读。
- [ ] 减少动态效果下无强制闪烁或持续大幅晃动。

## 5. 性能与数据保护验收（草案指标）

- 记录 Windows 版本、WebView2 版本、CPU、缩放和进程测量工具。
- `idle_healthy` 5min：目标 CPU 平均 <1%；内存 <150MB；未达成则记证据并优化，**不伪称性能已验证**。
- 1000 个模拟确认事件、100 个纪念记录后 UI 分页、搜索不卡顿。
- 模拟应用崩溃、写入失败、数据库锁竞争；数据不丢交易、不重复记账。
- 数据可本地导出/备份，清空明确二次确认。
