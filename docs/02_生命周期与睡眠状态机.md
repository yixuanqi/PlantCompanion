# 02｜生命周期、自动睡眠与唤醒状态机（实现真源）

> **最高优先级：**所有生命判断由 Rust 内核维护，UI 动画不能直接修改生命周期。`DEAD` 为不可逆终态；`SLEEPING` 是保护覆盖态，`WAKING` 只是视觉过程而不是新的生命阶段。

## 1. 数据维度分离

- `life_stage`: `HEALTHY` / `THIRSTY` / `DRY` / `CRITICAL` / `DEAD`。
- `activity_mode`: `ACTIVE` / `SLEEPING`；另记录 `sleep_reason` = `IDLE` / `LOCK` / `SUSPEND` / `MANUAL` / `QUIET_HOURS` / `RECOVERY`。
- `visual_transition`: `NONE` / `GOING_TO_SLEEP` / `WAKING` / `WATERING` / `GROWING` / `WITHERING`，**只影响渲染**。
- `active_elapsed_ms`: 本轮有效活动时间（暂停时保持不变）；`cycle_id` 绑定当前喝水周期。
- `instance_state`: `ALIVE` / `DEAD`；实例死亡时锁定 `died_at`，任何事件都不能从 `DEAD` 返回 `ALIVE`。

状态不是互斥的 7 个值：例如一株 `DRY` 的小薄荷可以 `SLEEPING`，醒来后仍 `DRY`。这样不会因为睡醒而自动变健康。

## 2. 默认计时方案（暂定，可配置）

- `T=45min`：当前提醒周期长度。
- `mild=0.70*T`，`dry=0.90*T`；`critical=T+10min`；`dead=T+20min`。
- `active_elapsed` 仅统计用户被判定在场且产品处于活跃时段的**有效活动时长**，不是从开始到当前的自然流逝时间。

| 有效活动时长 `e` | life_stage | UI/提醒 |
| --- | --- | --- |
| `0 <= e < 0.70T` | HEALTHY | 轻轻 idle，默认不弹 |
| `0.70T <= e < 0.90T` | THIRSTY | 叶片微垂，最多一条温和提醒可选 |
| `0.90T <= e < T+10min` | DRY | 叶片明显低垂；到 `e=T` 触发一次标准喝水提醒 |
| `T+10min <= e < T+20min` | CRITICAL | 枯黄明显，仅一次最后提醒 |
| `e >= T+20min` | DEAD | 将当前生命**一次性、事务性**标为死亡，记入纪念册 |

举例默认 T=45：健康到 31:30；THIRSTY 到 40:30；DRY 到 55:00；CRITICAL 到 65:00；之后 DEAD。**边界必须用毫秒整型比较，不以 UI 四舍五入文案判断。**

## 3. 时间推进、休眠、恢复语义

### ACTIVE

- Rust 依据**单调时钟增量**积累 `active_elapsed_ms`，禁止直接用 `Date.now()-start` 推断活动时长。
- 仅当 `activity_mode=ACTIVE` 且无其他暂停理由时更新；渲染端每 1s 显示剩余时间即可，内核低频调度亦可。
- 时间推进跨越多个边界，按时间顺序产出事件；副作用去重（同一事件 ID 最多一次）。

### SLEEPING

- `activity_mode=SLEEPING` 后保存当前 `life_stage / active_elapsed_ms / growth_progress`；健康状况不改善也不恶化，成长不增长、不掉进度。
- 入睡/唤醒只是 UI 动画叠加，不能修改 `life_stage`。
- 睡眠不触发常规提醒、币奖励、死亡、成长；手动睡眠不视为喝水。
- 唤醒后继续睡前剩余时间；如果醒前已有 `CRITICAL`，继续保持临界，允许用户选择喝水或手动暂停。
- DEAD 不允许入睡、不允许通过唤醒复活。

### 不同保护原因优先级

- 计算 `sleep_reasons: set`，而不是单个可覆盖标志，例如同时存在 `LOCK` 和 `MANUAL`。
- 只要集合非空就处于 SLEEPING，全部理由解除才进入 WAKING；防止解锁后错误解除用户主动暂停。
- 推荐：`LOCK` 锁屏立即保护；`SUSPEND` 休眠立即保护；`IDLE` 无操作超过阈值保护；`QUIET_HOURS` 用户指定非活跃时段保护；`MANUAL` 需用户或预设结束条件解除。

### 无输入检测时的关键公平性规则

**不能等到 10 分钟才发现用户不在，然后把这 10 分钟当成恶化并判死。** 推荐“待确认空闲窗口”机制：

1. 周期性从 Windows 用户会话读取最后输入时间（如 `GetLastInputInfo`）；检测到持续没有输入的区间时，这段区间属于**暂定时间**。
2. 如果无输入持续达到 10 分钟，向先前的 `last_input_at` 回溯确认 `IDLE` 保护，从最后一次输入起的暂定时间**不计入有效活动**。
3. 若 10 分钟以内有新输入，则将暂定时间并入 `active_elapsed_ms`，按顺序处理应发生的正常阶段事件。
4. 暂定区间内不提交不可逆死亡；先判定是否成为 `IDLE`，再决定结算。不可逆写入采用“已确认有效活动时间”。
5. 用户长时间观看视频或阅读、不产生输入时可能被误认为离开；提供关闭空闲自动睡眠的设置，并以后考虑更智能的例外模式。

**实现约束：**不是“发现 idle 时简单扣掉 10 分钟”，否则死亡已落库就无法撤回。要在状态机层保留 `confirmed_active_ms` + `pending_idle_ms` 或等效事件账本；待窗口确认才结算。详见 08 中的边界测试。

### 离线 / 崩溃 / 关机

- 应用没有运行的区间，不累计有效活动时间。正常退出时写入 checkpoint（当前 `confirmed_active_ms`、阶段、状态、时间戳）。
- 意外崩溃后，若最后活动区间归属不明，按保护原则**不追加未知的墙上时间**。重启后从记录的检查点恢复。
- 系统睡眠时可能停止/扭曲部分计时器；通过系统电源事件与单调时钟/会话变化纠偏，不把挂起墙上时间算到生命里。
- 系统时间被用户调整、夏令时切换，不允许影响生命周期；本地日期只用于纪念记录等展示，不参与重种资格或死亡判定。
- 存盘必须保证不可逆死亡与纪念日志原子性，不能出现已死亡但历史没记录的半状态。

## 4. 事件与状态转移

| 事件 | 前置条件 | 业务动作 | 动画/UI |
| --- | --- | --- | --- |
| `CONFIRM_DRINK` | ALIVE 且 ACTIVE | 有效记录本周期一次，重设 `active_elapsed=0`，生成 `cycle_id`；奖励可能受冷却限制 | WATERING → RECOVER → IDLE |
| `ENTER_SLEEP(reason)` | ALIVE | 将 reason 加到保护集合；冻结计时/成长 | GOING_TO_SLEEP → sleeping idle |
| `EXIT_SLEEP(reason)` | ALIVE | 移除指定 reason；若集合空则恢复 ACTIVE | WAKING → 当前阶段 idle |
| `TICK(dt)` | ALIVE 且 ACTIVE | 累计**已确认活动**时长，推导阶段 | 根据新旧阶段选择动画 |
| `TIMEOUT_DEATH` | 已确认活动 >= 死亡阈值 | 原子写 DEAD + 纪念记录 | WITHERING → DEAD 静态 |
| `APP_RESTART` | 已存储实例 | 加载 checkpoint、回收未完成暂定窗口，禁止追算离线时长 | 按实际已存阶段展示 |
| `REPLANT` | 当前无 ALIVE 且允许重种 | 新的 instance_id/generation，不复用旧实例 | GROW / ARRIVE |
| `CHANGE_SETTINGS` | 配置通过验证 | 新阈值应用下一周期（推荐），避免调参瞬间杀死植物 | 提示“下次喝水后生效” |

## 5. 伪代码（逻辑方向，非可直接编译源码）

```text
on_confirmed_active_delta(delta_ms):
  assert delta_ms >= 0
  if instance.state == DEAD or sleep_reasons not empty: return
  active_elapsed_ms += delta_ms
  next = stage_from_elapsed(active_elapsed_ms, config_snapshot)
  if next == DEAD:
      transaction(mark_instance_dead_once, insert_memorial_once, append_event_once)
  else:
      stage = next
      emit_stage_transition_if_changed()

on_sleep_reason_added(reason):
  if instance.state == DEAD: return
  sleep_reasons.add(reason)
  if first_reason: emit(ANIMATE_GO_TO_SLEEP)

on_sleep_reason_removed(reason):
  sleep_reasons.remove(reason)
  if sleep_reasons.empty() and instance.state == ALIVE:
      emit(ANIMATE_WAKE_UP)    # 不重置 active_elapsed_ms / 不重置 life_stage

on_confirm_drink(event_id):
  if instance.state == DEAD: return REJECT_DEAD
  if sleep_reasons not empty: return ASK_WAKE_OR_REJECT
  if event_id already_handled: return IDEMPOTENT
  save_drink_confirmation_once(event_id, cycle_id)
  active_elapsed_ms = 0
  start_new_cycle()
  emit(ANIMATE_WATER_AND_RECOVER)
```

## 6. 特殊操作说明

- **睡着时点击植物：**第一下唤醒（或显示“唤醒小蘑菇？”），不能同时算喝水；第二下才可以确认“我喝水了”。避免意外点击。
- **手动休息 1 小时：**`MANUAL` 原因附加到睡眠集合，计时结束仅移除该原因；如仍锁屏，不唤醒。
- **今天别提醒：**设为 `QUIET_HOURS/USER_MUTE` 保护至当日活跃时段结束；结束后按睡眠设置恢复。默认不做偷偷继续扣生命值的“静音但恶化”。
- **喝水点击已枯死的植物：**只弹纪念卡或提示，不进入恢复动画。
- **重复事件/反复唤醒：**事件 ID 幂等；播放时动画重入按 05 号文档优先级处理。

## 7. 本文需遵守的硬门禁

- 睡眠 12 小时醒来，剩余时间误差不得超过本地计时粒度和 checkpoint 容差；**不能减少 12 小时**。
- 崩溃前 `THIRSTY`，重开后不得无故变 `DEAD`。
- 生命 A 死亡，种植同品种 B，也必须 B 为全新 instance_id；绝不能修改 A 的死亡时间。
- 只看前端动画做出“复活”效果，不应改变后端生命实例。
