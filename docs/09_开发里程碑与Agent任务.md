# 09｜开发路线与 Agent 可执行任务

采用 Loop Engineering + TDD：一项任务=实现 + 测试 + 验收 + 证据。**不是按 UI 菜单先堆一大堆功能**，而是先打通时钟和生命状态这条底座。

## Milestone 0｜基座初始化（P0）

- 创建 Tauri 2/Rust/TypeScript Windows 项目及 CI；分离 domain/application/platform/render 目录。
- 架构约束编译检查、版本锁定、稳定的日志与错误处理；窗口最初只放一个灰盒植物占位图。
- **完成标准：**可以跑最小 Windows 安装/开发包，主屏托盘菜单控制浮窗，不抢焦点；有构建说明。

## Milestone 1｜纯 Rust 生命周期（最高优先级）

- `LifeEngine` 枚举、事件、`stage_from_elapsed`、实例不可逆死亡。
- 时间注入与模拟时钟、睡眠理由集合、确认活跃时间/暂定 idle 机制。
- 编写 08 的 L-01 至 L-17；实测关键阈值边界。
- **完成标准：**不需要 WebView 也能跑完整“活着/缺水/睡眠/唤醒/死后重种”模拟；无误死亡。

## Milestone 2｜持久化和系统监测

- SQLite 事务和迁移、checkpoint、幂等命令和日志。
- Windows `GetLastInputInfo`、锁屏/解锁、电源挂起/恢复适配器；提供 FakeAdapter 供测试。
- 实现主窗口、气泡的生命周期；托盘一键睡眠/唤醒与退出。
- **完成标准：**真机锁屏、休眠和退出后继续状态正确；不把离线时间算活跃时间。

## Milestone 3｜两种植物美术资产生产（可与 M1、M2 并行）

- 先审核小薄荷和小蘑菇**健康姿态母版**，统一色调、盆型、线条和视角；不能各画各的。
- 输出分层资源，制作 4 类主要枯萎关键姿态 + 死亡专用母版 + 睡眠姿态。
- 做 `idle`, `transition_stage`, `water_recover`, `go_to_sleep`, `wake_up`, `death_once` 资源/代码。
- **完成标准：**两株展示在同一张 128 DIP 桌面预览中均自然、统一、无五官；动画平稳。

## Milestone 4｜桌面交互与风格统一

- 植物浮窗、手绘气泡、鼠标点击/悬停/拖拽、托盘菜单。
- 设置窗：提醒、睡眠、工作时段、显示、动效等。
- 台词使用 JSON key 读取且支持角色差异；显示当前生命阶段与有效活动计时。
- **完成标准：**用户无需指导能在 30 秒内完成一次确认喝水；睡眠点击不误记喝水。

## Milestone 5｜商店、图鉴、纪念花园（最小闭环）

- 种子铺两植物卡片、种下新生命、品种永久解锁、币和成长流水。
- 图鉴已拥有 / 未发现状态；纪念花园每代历史数据及空态。
- 未来的隐藏品种只支持配置和剪影占位，不扩展资产工作量。
- **完成标准：**死亡后不可复活；下一次合法重种是新 instance_id；数值口径一致。

## Milestone 6｜回归与发布候选

- 按 08 号文档做 Win10/11、DPI、多屏、锁屏、休眠、退出和崩溃回归。
- 用真实硬件测 idle CPU/内存；检查透明 hit-test、动画持续性和气泡可读性。
- 写安装、升级、卸载、数据备份/清空说明；打包签名策略待独立决策。

## 可直接交给 Agent 的任务模板

```markdown
任务：实现 <唯一工作项>。
依据：README.md；docs/02_生命周期与睡眠状态机.md；相关专题文档。
范围：仅修改 <模块/文件范围>，不得扩大物种数或添加脸部表情。
先写测试：列出正常/边界/异常用例，失败后再实现。
实现要求：业务真源在 Rust；前端只能发送意图与渲染快照。
验收：运行 <具体命令>；附日志、用例结果、截图/录屏。
输出：变更摘要、测试证据、已知风险、后续建议。
必须解释：是否会造成误死亡、金币重复奖励或动画状态漂移。
```

## 首批任务建议（严格依次）

1. `TASK-001`：初始化 Rust `LifeEngine` 类型 + 边界单测。
2. `TASK-002`：实现睡眠理由集合与有效活动时间模型 + 模拟闲置测试。
3. `TASK-003`：实现 SQLite 生命/纪念幂等事务与重启恢复。
4. `TASK-004`：Tauri 透明植物窗与托盘最小原型。
5. `TASK-005`：绘制并审核两株健康母版，拿到可拆分图层。
6. `TASK-006`：渲染两株 idle / 缺水 / 浇水 / 睡眠/唤醒动画最小闭环。
7. `TASK-007`：设置与气泡统一 UI，接入模拟状态再接真实事件。
8. `TASK-008`：种子铺 / 图鉴 / 纪念花园。
9. `TASK-009`：整体验收与 Windows 兼容回归。

> 每一步按对应验收打勾后再进入下一步，避免 Agent 同时处理 UI、美术和系统底层造成大量返工。
