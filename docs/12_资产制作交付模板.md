# 12｜美术资产交付模板与角色扩展接入

## 1. 每种植物交付文件清单

```text
plant_<id>/
  00_reference/                参考概念图、色板、尺寸规范
  01_source/                   可编辑分层源文件及图层说明（不可缺）
  02_exports/                  各个分离图层透明素材，统一画布与坐标
  03_poses/                    healthy/thirsty/dry/critical/dead/sleep 关键姿态
  04_fx/                       水滴/微风/掉落物，必要时复用公共 FX
  05_preview/                  96/128/160 DIP、浅/深壁纸、状态对比、动效预览
  manifest.json                anchor/coordinate/art_version/animation references
  CHANGELOG.md                 素材更新记录
```

## 2. 交接的最低要求

- **母版**：至少一张高质量健康中性母版，带可编辑图层与透明导出；角色不是从设计板图片中抠出来的。
- **状态母版**：HEALTHY / THIRSTY / DRY / CRITICAL / DEAD 五个独立可用的状态关键姿态，保留同一花盆锚点。
- **睡眠姿态**：睡眠叠加姿态与睡前健康/缺水主要状态兼容；可额外制作状态特例，但不能造成健康重置的错觉。
- **动画**：至少 idle_healthy、stage_transition、water_recover、go_to_sleep、sleep_idle、wake_up、death_once；每个动作须有动效预览，不允许只交几张图。
- **对话**：UI 气泡用可编辑矢量/CSS 边框或九宫格切片；气泡不烘焙具体文字。
- **粒子**：水滴、星点、小叶子等独立图层，可复用公共素材；不画五官。

## 3. 建议 manifest 结构（结构示例）

```json
{
  "species_id": "mint",
  "art_version": "0.1.0",
  "canvas": { "width": 512, "height": 512, "unit": "px" },
  "anchors": { "pot_base": [256, 455], "stem_root": [256, 340] },
  "layers": [
    { "id": "pot", "path": "02_exports/pot.png", "z": 10 },
    { "id": "stem", "path": "02_exports/stem.png", "z": 20 },
    { "id": "leaf_left_01", "path": "02_exports/leaf_left_01.png", "z": 30 }
  ],
  "poses": ["healthy", "thirsty", "dry", "critical", "dead", "sleep_overlay"],
  "animations": ["idle_healthy", "transition_stage", "water_recover", "go_to_sleep", "sleep_idle", "wake_up", "death_once"],
  "face_elements_allowed": false
}
```

## 4. 新品种接入顺序（未来再做）

1. 提交一张与首发两株并排的中性健康母版，先通过画风评审。
2. 拆层，补完整生命周期 + 睡眠姿态；提供 动画/气泡角色特征。
3. 在 `plant_species.v1.json` 新增品种 ID/解锁条件/资源版本，不修改共用生命周期枚举。
4. 对跨品种状态的视觉力度做对比测试；更新图鉴预览与缩略图。
5. 必须通过 08 的视觉回归才加入正式植物库。

## 5. 美术评审常见失败模式

- 每个状态独立生成一张图造成花盆、叶片数量、俯仰角不断变化。
- 只有整体 PNG，没有叶片/伞盖分层，程序化 idle 只能整张摇晃。
- 一株偏儿童简笔画、另一株偏厚涂水彩，视觉世界观不统一。
- 睡眠看起来像死亡；缺水恢复后突然长出原先没有的叶子。
- 设计板中的对话文字和图标被连同角色一起裁剪，导致窗口中重复 UI。
